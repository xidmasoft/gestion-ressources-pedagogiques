## 2024-09-30 - [PHP 8+ Strict Typing TypeError DoS]
**Vulnerability:** In PHP 8+, passing arrays to functions that strictly expect strings (like `hash_equals()`, `password_verify()`, `trim()`, `htmlspecialchars()`) causes a fatal `TypeError`, stopping script execution entirely. Unauthenticated endpoints and critical operations passing raw `$_POST` or `$_GET` values directly to these functions were vulnerable to unauthenticated Denial of Service (DoS) attacks by sending arrays instead of strings (e.g. `email[]=a`).
**Learning:** The upgrade to PHP 8 introduced strict typing for internal functions. While beneficial for code quality, it turns previously silent failures or warnings into fatal errors, creating new DoS vectors if inputs are not explicitly type-checked before use.
**Prevention:** Always validate that user inputs are strings (using `is_string()`) before passing them to internal PHP functions that enforce string type hints, especially in authentication controllers or security-critical helpers like CSRF verification.
