## 2024-05-24 - DoS Risk in CSRF Verification via TypeError
**Vulnerability:** The `verify_csrf()` function used PHP's `hash_equals()` to compare the session CSRF token with the POSTed CSRF token. However, it did not explicitly verify that both tokens were strings. In PHP 8+, passing a non-string (like an array, which an attacker can easily submit via `csrf_token[]=123`) to `hash_equals()` throws a fatal `TypeError`. If an application does not catch this exception globally, this results in a 500 Internal Server Error, leading to a potential Denial of Service (DoS) vulnerability on all endpoints protected by CSRF checks.
**Learning:** Functions that enforce strict typing in PHP 8+ (like `hash_equals()`, `password_verify()`, etc.) can introduce DoS vulnerabilities if user inputs are passed to them without explicit type validation first.
**Prevention:** Always explicitly validate the types of user inputs (e.g., using `is_string()`) before passing them to native PHP functions that expect specific types and throw exceptions on type mismatches.
